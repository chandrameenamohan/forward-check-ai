# Baseline and first attack, 2026-10-02

Before the fixes the baseline was 12 of 18 properties PASS with 16 of 16 guards hit. After them it is 18 of 18 and
16 of 16; `chaos 8` passed 8 of 8 (graph-unavailable x4, app-killed x2, model-slow, model-unavailable) and
`model-frozen` passed. Each failure below flipped from FAIL to PASS on the rebuilt image and has a regression
test in the normal suite.

## 1. A false claim could be shown as LIKELY TRUE (P0, verdict-never-inverts-the-judge)
- **Sequence:** the Judge submits `likely-false` with confidence 97 (it means "97% sure it is false").
- **False belief:** the confidence gate takes the score as the truth and the category as the mistake.
- **Consequence:** the stored and displayed verdict was `likely-true` at 97.
- **Smallest fix:** the gate never moves a verdict to the opposite pole; a Judge that contradicts itself becomes
  `unverified`. `src/formatter/confidence-gates.ts`.

## 2. A claim could stay pending or investigating for ever (P0, accepted-claim-reaches-terminal-status)
- **Sequence A:** the same claim is asked twice through the web chat. The chat makes a row, then the pipeline
  answers from its cache with the first row's id. **Consequence:** the second row stayed `pending` and its page spun.
  **Fix:** on a cache hit the pipeline finishes the caller's own row. `src/orchestrator/pipeline.ts`.
- **Sequence B:** the app is killed with investigations running. **False belief:** a row marked `investigating`
  has a process working on it. **Consequence:** it stayed `investigating` after the restart.
  **Fix:** at startup every pending or investigating row is marked `failed`. `src/index.ts`.
- **Also found by hand before the harness:** a pipeline error in the chat route left the row `investigating`.

## 3. One WhatsApp message could be investigated twice (P0, one-investigation-per-delivered-message)
- **Sequence:** Meta delivers a webhook again because the first acknowledgement was slow.
- **False belief:** every webhook is a new message.
- **Consequence:** two investigations and two answers for one message, at about a dollar each.
- **Smallest fix:** the message router ignores a platform message it is already handling or has a row for.

## 4. Real WhatsApp messages were refused as forged (P1, signed-webhook-always-accepted)
- **Sequence:** Meta signs the bytes it sends, and escapes slashes and non-ASCII characters in them.
- **False belief:** `JSON.stringify(req.body)` gives those bytes back. The raw body was never kept in `createApp`
  (the unit test built its own Express app that did keep it, which is why it passed).
- **Consequence:** 403 for any message containing a slash, an accent or an emoji, so most links.
- **Smallest fix:** keep the raw body in `express.json`'s `verify`. `src/server/app.ts`.

## 5. A WhatsApp user could be left without an answer (P1, whatsapp-user-always-answered)
- **Sequence A:** the Graph API is down for a few seconds when the verdict is sent. **Consequence:** the send was
  logged and dropped. **Fix:** sends retry three times (1 s, 3 s, 9 s) on a network error, 429 or 5xx.
- **Sequence B:** the app is killed mid-investigation. **Fix:** at startup the people whose investigations were
  interrupted are sent an apology (WhatsApp and Telegram; only WhatsApp is in the slice).

## 6. A link could make the app read its own machine (P1, no-loopback-fetch-from-user-url)
- **Sequence:** a claim contains `http://localhost:3000/`.
- **False belief:** a URL in a message points at the public web.
- **Consequence:** the app fetched its own page and sent the content to the model.
- **Smallest fix:** the fetch refuses loopback, private and link-local addresses, and checks every redirect.
  Not covered: a host that changes its DNS answer between the check and the fetch.

## Behaviour worth knowing that is not a bug
- With no Brave key, each search is a Haiku session of 20 to 40 s. The Judge's timeout was raised to 300 s and a
  turn's tool calls now run in parallel.
- A self-contradicting Judge now yields `unverified` with the Judge's own score, so the page can read
  "UNVERIFIED 97%". The Judge's prompt asks for a truth score, so this should be rare.
